## Добавленные случаи

ImportBatchCommitTest:

1. Шесть некорректных батчей: повтор ID, несоответствие checkpoint числу ID,
   несоответствие fetched и checkpoint, отсутствие деталей отказа, чужой ID отказа,
   два отказа для одного ID. Проверяется, что sink не вызывается и состояние не меняется.
2. Ранее подтверждённый ID в новой пачке с актуальным checkpoint отклоняется до sink.
3. Resume без явного лимита наследует исходный лимит и получает новый owner_token.
4. Другой явный лимит отклоняется без передачи владения и изменения статуса.
5. Resume выбирает последний прогон нужного provider/source, не затрагивая остальные.
6. Отсутствующий подтверждённый отказ делает resume небезопасным и вызывает ошибку.

ImportReliabilityTest:

1. Resume без существующего прогона начинает новый запуск.
2. Запуск без resume повторно обрабатывает те же внешние ID в другом run;
   журнал ID обеспечивает уникальность внутри прогона, а не между прогонами.

## Что ещё требуется

1. Выполнить шесть PostgreSQL-тестов на изолированной PostgreSQL-БД. В текущем
   запуске они пропущены из-за SQLite. Они проверяют отдельную lock-сессию,
   reconnect, потерю lock backend, rollback и конкурирующий resume. In-memory
   lock в остальных тестах не доказывает межпроцессные гарантии.
2. Исправить JSON-контекст INF, -INF и NAN и добавить интеграционный тест:
   одна запись отклонена, соседние сохранены, отказ/ID/checkpoint согласованы,
   resume не застревает. Дефект подтверждён отдельно: присваивание текущего
   контекста ImportRejection вызывает JsonEncodingException.
3. Применить и проверить отдельно нужные изменения из stash: исправление
   afterCommit-логирования, LogCandidateSinkTest и проверки пустой финализации
   находятся в stash@{0}, но не в проверяемом checkout. Не следует считать их
   гарантией текущей ветки до применения и повторного запуска.
4. При реализации сохраняющего sink проверить настоящий каталог вместе с
   checkpoint: повторный запуск, rollback, пустую финальную пачку, external_ids
   и outbox. Сейчас оркестратор подключён к LogCandidateSink, а транзакционные
   тесты sink используют вспомогательную таблицу saved_candidates.

Измерения памяти не выполнялись и не добавлялись в задачу.
