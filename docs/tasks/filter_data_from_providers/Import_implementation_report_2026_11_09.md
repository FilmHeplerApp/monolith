## 3. Исправление INF, -INF, NAN

В ProviderTitleToCandidateMapper нечисловые конечные значения явно представляются
строками INF, -INF, NAN в контексте ProviderTitleMappingException и тексте ошибки.
Обычные конечные значения вне диапазона сохраняют числовой тип.

До исправления все три новых интеграционных случая падали. INF и -INF приводили
к JsonEncodingException при сохранении ImportRejection. На PHP 8.5 приведение NAN
к строке также вызывало предупреждение, превращаемое Laravel в исключение.
Поэтому исправление использует явный match без приведения NAN к строке.

Теперь для каждого из трёх значений подтверждено:

- первая и третья записи принимаются;
- вторая получает один отказ malformed с JSON-совместимым контекстом;
- fetched/checkpoint = 3, accepted = 2, rejected = 1;
- журнал содержит три ID;
- resume завершённого прогона не повторяет записи и не создаёт второй отказ.

## 4. Добавленные/усиленные проверки

### Оркестратор и recorder

Сохранены 13 случаев последнего аудита: несогласованные батчи до вызова sink,
повтор уже подтверждённого ID с новым checkpoint, наследование/отклонение лимита,
выбор последнего нужного provider/source, повреждённый отчёт отказов, новый прогон
при отсутствии истории и повторная обработка ID без resume.

Дополнительно проверены:

- пустой источник;
- пачка только из отказов;
- ровно полный батч с последующей пустой финализацией;
- нулевой и отрицательный лимит без создания прогона;
- нулевой и отрицательный интервал checkpoint;
- сохранение исходной ошибки при дополнительном отказе abort();
- запрет привязки нового снимка к legacy-checkpoint без исходного fingerprint.

### Диагностическое логирование

Проверены здоровый logger, ошибка промежуточного commit, ошибка финального commit
и отказ logger для всех сообщений. Тесты наблюдают фактическое состояние БД
в callback: транзакция уже завершена, checkpoint и статус подтверждены.
Проверяется попытка выпуска всех сообщений и резервная диагностика.

Отдельный изолированный процесс подменяет только namespaced error_log для sink
и заставляет его бросать исключение. Подтверждены три попытки резервной записи,
успешное завершение импорта и отсутствие распространения ошибок. Подмена не
попадает в другие тесты и не загружается производственным приложением.
Существующая проверка отсутствия сообщений после rollback также проходит.

### Настоящий CatalogBulkWriter

Пять новых случаев группы catalog_import используют действующий CatalogBulkWriter,
таблицы titles, title_attributes, attribute_definitions, attribute_options
и действующий EloquentImportRunRecorder:

1. Каталог и checkpoint подтверждаются вместе; второй прогон обновляет те же
   записи без дубликатов тайтлов и атрибутов.
2. Исключение после записи каталога откатывает все четыре каталожные таблицы
   и журнал; последующий resume успешно сохраняет единственный комплект записей.
3. Ошибка вставки журнала ID после записи каталога откатывает весь батч.
4. Пустой финальный батч завершает прогон без изменения существующего тайтла
   и без повторных связей атрибутов/ID.
5. Ошибка пустой финализации откатывает изменение тайтла, сохраняет предыдущий
   checkpoint и не устанавливает completed.

На PostgreSQL каждый тест каталога использует отдельную временную схему,
которая удаляется в tearDown. Запись выполняется реальными writer и recorder,
без подмены writer на stub.

Подтверждены шесть сценариев PostgreSQL:

- reconnect рабочего соединения не освобождает отдельный advisory lock;
- завершение lock backend обнаруживается без скрытого reconnect;
- блокировка другой сессии запрещает второй импорт;
- конкурирующий resume ждёт row lock и видит подтверждённый checkpoint;
- ошибка после записи sink откатывает батч;
- реальная потеря lock-сессии после записи sink откатывает батч.
