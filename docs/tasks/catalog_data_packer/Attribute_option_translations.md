# Согласование переводов опций между пачками импорта

## Проблема

`AttributeOptionBulkWriter` делает upsert опций по уникальному индексу `(attribute_id, value_ru)`.
Раньше при конфликте `value_en` всегда перезаписывался входящим значением. Если пачка приносила
опцию без английского перевода (провайдер его не отдаёт), сохранённый перевод затирался на `NULL`.

## Правило

Опция сопоставляется по `(attribute_id, value_ru)`, то есть по типу контента, коду атрибута
и русскому значению. Ключ берётся из результата `CatalogPacker`: `value_ru` уже содержит русский
текст или действующий fallback на английский. Второй нормализатор ключей не вводится.

- Если входящий `value_en` заполнен, он заменяет сохранённый перевод.
- Если входящий перевод отсутствует, остаётся сохранённый.
- Если перевода нет в обоих источниках, результат — `null`.

Пустые строки нормализует `LocalizedText`. Отсутствие перевода не является командой его удалить.

Дедупликация внутри пачки остаётся в `CatalogPacker`: среди нескольких заполненных английских
значений одной опции сохраняется первое. Между пачками заполненное входящее значение имеет
приоритет перед каталогом.

## Реализация

Правило выполняет сама база данных в upsert `AttributeOptionBulkWriter`:

```sql
INSERT INTO attribute_options (...) VALUES (...)
ON CONFLICT (attribute_id, value_ru) DO UPDATE
SET value_en = COALESCE(excluded.value_en, attribute_options.value_en), updated_at = excluded.updated_at
```

`excluded.value_en` — входящий перевод, `attribute_options.value_en` — сохранённый.
Предварительное чтение опций, согласование в PHP и дополнительные блокировки не нужны.

Правило живёт в writer, поэтому соблюдается для любого вызывающего кода: импорта через
`CatalogImportBatchSaver`, прямого вызова `CatalogBulkWriterContract` и будущих источников.

## Ответственность классов

- `CatalogCandidateSink` собирает тайтлы и передаёт их `CatalogImportBatchSaver`.
- `Application/Import/Services/CatalogImportBatchSaver` проверяет определения атрибутов через
  `CatalogAttributeDefinitionValidatorContract`, упаковывает пачку `CatalogPacker` и передаёт её
  `CatalogBulkWriterContract`.
- `CatalogPacker` остаётся чистым преобразователем без доступа к каталогу.
- `AttributeOptionBulkWriter` выполняет upsert с правилом выбора перевода.

## Транзакция и конкурентность

Производственная СУБД — PostgreSQL. Пачка записывается внутри внешней транзакции
`EloquentImportRunRecorder::commit` вместе с checkpoint.

`INSERT ... ON CONFLICT DO UPDATE` в PostgreSQL атомарен для каждой строки:

- если другая транзакция уже вставила или обновила ту же опцию и ещё не закоммитила,
  upsert ждёт её завершения на блокировке строки (или записи уникального индекса);
- после её commit выражение `COALESCE` вычисляется по актуальной закоммиченной версии строки,
  поэтому перевод, сохранённый параллельным импортом, не теряется;
- после её rollback вставка продолжается как новая.

Импорты ждут друг друга только при записи одной и той же опции и только до коммита транзакции,
которая её записала. Справочник определений (`attribute_definitions`) не блокируется на запись,
поэтому пачки с общими атрибутами (жанры, страны) обрабатываются параллельно.
Валидатор определений берёт shared locks, совместимые между импортами.

Ошибка записи откатывает опции, тайтлы и остальную запись пачки вместе с checkpoint.
SQLite используется для функциональных тестов и поддерживает тот же синтаксис `excluded`,
но гарантии конкурентности проверяются только на PostgreSQL.

## Проверки

- Сохранение и замена перевода между пачками, сохранение ID опции и отсутствие дублей.
- Отсутствие перевода в обоих источниках, fallback на английский текст.
- Разделение типов контента и кодов атрибутов, согласование отдельно для каждой опции пачки.
- Правило работает при прямом вызове writer без `CatalogImportBatchSaver`.
- Сохранение пачки не читает опции из каталога.
- Rollback внешней транзакции, отсутствие запросов для пустой пачки.
- PostgreSQL (`PostgresCatalogOptionTranslationTest`, запуск с `DB_CONNECTION=pgsql`): два
  независимых процесса. Пачка без перевода ждёт commit параллельной транзакции и сохраняет её
  перевод. Проверяются новая опция, существующая без перевода и обновляемый перевод.
- Существующие тесты sink проверяют общую атомарность каталога и checkpoint.
