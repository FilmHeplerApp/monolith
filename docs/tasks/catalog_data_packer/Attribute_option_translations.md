# Согласование переводов опций между пачками импорта

## Правило

Опция сопоставляется по `(content_type_code, attribute_code, value_ru)`.
Ключ берётся из результата `CatalogPacker`: `value_ru` уже содержит русский текст
или действующий fallback на английский. Второй нормализатор ключей не вводится.

Если входящий `value_en` заполнен, он заменяет сохранённый перевод.
Если входящий перевод отсутствует, используется сохранённый.
Если перевода нет в обоих источниках, результат — `null`.
Пустые строки нормализует `LocalizedText`. Отсутствие перевода не является командой его удалить.

Дедупликация внутри пачки остаётся в `CatalogPacker`: среди нескольких заполненных
английских значений одной опции сохраняется первое. Между пачками заполненное входящее
значение имеет приоритет перед каталогом.

## Ответственность классов

- `CatalogCandidateSink` собирает тайтлы и передаёт их `CatalogImportBatchSaver`.
- `Application/Import/Services/CatalogImportBatchSaver` координирует чистую упаковку,
  транзакцию, проверку определений, чтение, согласование переводов и запись.
- `CatalogPacker` остаётся чистым преобразователем без доступа к каталогу.
- `AttributeOptionReaderContract::read()` принимает список `AttributeOptionData`
  с уже сформированным `value_ru` и возвращает список найденных `AttributeOptionData`.
- `EloquentAttributeOptionReader` читает только запрошенные ключи, соединяя опции
  с определениями. Сценарий запрашивает только опции без входящего английского перевода;
  если все переводы заполнены, чтение опций не требуется.
  Повторные ключи удаляются, запрос ограничен 250 ключами
  и максимум 750 параметрами. Пустой список не вызывает запросов.
- `AttributeOptionTranslationResolver::resolve()` принимает входящие и сохранённые
  списки `AttributeOptionData`, возвращает новый согласованный список, не изменяя исходные DTO.
- `CatalogImportBatchTransactionContract::run()` принимает список `CatalogTitlePackData`
  и callback чтения и записи; callback выполняется после получения блокировок.
- `CatalogAttributeDefinitionValidatorContract` позволяет сценарию Application проверять
  определения через существующую инфраструктурную реализацию.
- `AttributeOptionBulkWriter` получает согласованные DTO и выполняет обычный upsert.
  Правила выбора перевода в writer нет.

## Транзакция и конкурентность

Производственная СУБД — PostgreSQL. При обычном уровне изоляции READ COMMITTED
после ожидания блокировки запрос опций получает актуальные зафиксированные значения.

Порядок работы:

1. Чистая упаковка исходной пачки.
2. Открытие транзакции или savepoint внутри транзакции checkpoint.
3. Эксклюзивная блокировка строк всех определений, упомянутых в атрибутах тайтлов.
4. Проверка определений, включая прежние shared locks.
5. Пакетное чтение существующих опций.
6. Согласование переводов в Application.
7. Запись каталога через `CatalogBulkWriterContract`.
8. Commit внешней транзакции импорта с checkpoint.

Блокировки определений берутся до shared locks валидатора. Повышение ранее полученных
shared locks до эксклюзивных не требуется.

Определения сортируются по типу контента и коду в бинарном порядке. PostgreSQL использует
`COLLATE "C"`, согласованный с `strcmp` при разбиении на группы по 250 ключей.
Это задаёт единый порядок блокировок для пачек, пришедших в разном порядке.
Блокируются все используемые определения, включая числовые и логические, чтобы
последующая проверка не вводила другой порядок ожидания между импортами.

Блокировка родительского определения защищает также ещё не существующие опции.
Для отсутствующих определений валидатор завершает пачку ошибкой: импорт не создаёт
их автоматически. Существующий уникальный индекс `(attribute_id, value_ru)` сохраняется.

Чистая пачка может быть подготовлена заранее с `value_en = null`, но читать сохранённый
перевод и согласовывать его разрешено только после получения блокировок.
Блокировки удерживаются до commit/rollback самой внешней транзакции. Ошибка записи
откатывает согласованные опции, тайтлы и остальную запись пачки; внешний recorder
также откатывает checkpoint.

Все импорты, конкурирующие за справочник, должны использовать `CatalogImportBatchSaver`.
Прямой вызов технического writer не выполняет этот протокол согласования.
Пачки одного определения сериализуются; разные определения могут обрабатываться параллельно.
SQLite используется для функциональных тестов, но не доказывает гарантии блокировок PostgreSQL.

## Проверки

- Правила выбора перевода, отсутствие мутации DTO, разделение составных ключей.
- Последовательные пачки, сохранение ID опции и отсутствие дублей.
- Fallback на английский текст, отсутствие перевода в обоих источниках.
- Пакетность и ограничение размера запросов, отсутствие чтения для пустой пачки.
- Rollback после записи и rollback внешней транзакции.
- PostgreSQL: два независимых процесса. Подготовленная пачка без перевода ждёт
  внешнего commit и затем сохраняет актуальный перевод другого процесса.
  Проверяются новая опция, существующая без перевода и обновляемый перевод.
- Существующие тесты sink проверяют общую атомарность каталога и checkpoint.
