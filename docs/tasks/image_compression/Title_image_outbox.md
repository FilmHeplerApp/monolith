# Асинхронная обработка изображений каталога

Реализовано 2026-11-13 в ветке соединения оркестратора с каталогом.

## Транзакция импорта

CatalogCandidateSink после writer вызывает CatalogImageRequestRecorder в той же
транзакции recorder. Вместе подтверждаются titles, атрибуты, last_synced_at,
title_image_requests, title_image_outbox, журнал ID и checkpoint. При ошибке
журнала откатываются и задания изображений. Сетевые запросы в этой транзакции
не выполняются. Буфер коллизий и правила external_ids этим изменением не затронуты.

Одна строка title_image_requests описывает текущий запрос для пары title_id/kind.
Виды poster и banner независимы. Хранятся source_url, SHA-256 URL, version,
status, attempts, processing_token, lease_expires_at, retry_at и last_error.
Исходный URL не записывается в poster_key/banner_key.

Состояния:

- pending — запрос ожидает публикации или повторной попытки;
- processing — воркер получил токен обработки и аренду;
- ready — все варианты этого изображения сохранены и ключи применены;
- failed — постоянная ошибка или исчерпаны попытки.

Без URL новая задача не создаётся. Отсутствие URL при повторном импорте не удаляет
рабочие изображения и не отменяет существующий запрос. Тот же URL у активного или
готового запроса не создаёт новую версию. Новый URL меняет version, закрывает старые
события outbox и создаёт новое. Повторный импорт failed-запроса создаёт новую версию
с новым бюджетом попыток. Если старые ключи и URL-хеш уже совпадают, существующее
изображение признаётся готовым без повторной загрузки.

## Доставка через outbox

images:publish-outbox запускается scheduler каждую минуту с mutex TTL 5 минут; за один вызов по умолчанию
рассматриваются 100 событий. Можно выполнить вручную:

```bash
php artisan images:publish-outbox --limit=100
```

Publisher выбирает доступные события в порядке available_at/id, резервирует их
короткой транзакцией (PostgreSQL FOR UPDATE SKIP LOCKED), затем отправляет
ProcessTitleImageJob вне транзакции. Задание идёт в существующую очередь images.
Публикация не завершает событие: completed_at записывается только при успешной
обработке, окончательной ошибке либо смене версии. Поэтому падение до отправки,
потеря сообщения очереди и неопределённый результат отправки допускают повторную
доставку. Ошибка очереди сохраняется в outbox.last_error с отложенным повтором.

Пока действует processing-аренда, повторная публикация переносится до её истечения.
Доставка at least once: дубли ожидаемы, повторная работа отсекается в claim().
Новые ожидающие события имеют приоритет перед повторной доставкой более поздних
available_at, поэтому повторные сообщения не блокируют ещё не опубликованный хвост.

## Обработка и защита от устаревшего воркера

IngestTitleImageHandler получает работу через TitleImageRequestRepositoryContract.
Claim проверяет version, status, retry_at и аренду, увеличивает attempts и выдаёт
уникальный processing_token. Загрузка и StoreRemoteImageHandler выполняются вне
транзакции. Используются существующие downloader, компрессор и storage.
Постер формирует full и thumb; banner обрабатывается отдельным заданием.

Завершение сначала блокирует title, затем request — тот же порядок, что при импорте.
Версия и processing_token проверяются повторно. Только действующий владелец атомарно
обновляет ключи, source hash, ready и completed_at outbox. Изображения не изменяют
last_synced_at и updated_by: это не повторная синхронизация содержимого каталога.
Title::imageRequests() позволяет читать отдельные состояния, они не подменяют
is_incomplete, который описывает полноту исходных данных.

Если за время загрузки пришёл новый URL или другой воркер получил аренду той же
версии, старый результат в titles не применяется. Его новый временный префикс
удаляется. Рабочие ключи сохраняются до успешной замены. Старые управляемые префиксы
удаляются после commit. Чистка ограничена UUID-префиксами titles/posters и
titles/banners. Ошибка удаления не отменяет уже сохранённое изображение.

Если подтверждение commit потеряно, новые файлы не удаляются: неизвестно, стали ли
они рабочими. При аварийном завершении процесса между записью объектов и фиксацией
ключей также возможны объекты без ссылок. Сборщик таких объектов по возрасту и
ссылкам — отдельное обслуживание хранилища; текущая реализация предпочитает
оставить лишний объект, а не удалить потенциально рабочий.

## Ошибки и повторы

Download/storage ошибки повторяются с Retry-After либо images.download.default_retry_seconds.
UnsupportedImageException и ImageProcessingException переводят запрос в failed:
успешный возврат старого handler не используется как признак ready.
Неожиданные ошибки записываются и получают ограниченный бюджет повторов.
Погибшие processing-воркеры восстанавливаются после истечения аренды; такие попытки
также учитываются, бесконечной обработки одной версии нет.

Настройки images.ingestion:

- max_attempts = 3;
- lease_seconds = 300, минимум 240 при timeout задания 180;
- redelivery_seconds = 360, минимум 240.

Повторами управляют БД и outbox. У ProcessTitleImageJob tries=1; для продолжения
после падения воркера не требуется успешный failed-callback Laravel.

## Развёртывание и совместимость

Сначала применяются миграции, затем перезапускаются долгоживущие воркеры Horizon
и scheduler. Horizon уже настроен на images. Требуется работающий scheduler либо
регулярный запуск images:publish-outbox внешним планировщиком.

Миграция 2026_11_13_000002_create_title_image_requests_and_outbox создаёт обе таблицы.
Rollback удаляет их в порядке зависимостей, сохраняя titles и существующие ключи.
Миграция сама не создаёт задания для старых тайтлов: запросы появляются при импорте.
Существующие IngestTitleImagesJob/IngestTitleImagesHandler сохранены для совместимости;
новый импорт использует только версионированный ProcessTitleImageJob. Сетевые вызовы
и ошибки новых запросов не проходят через старый handler, который часть ошибок
только логирует. Новые вызывающие стороны должны использовать новый механизм.

## Проверки

TitleImagePipelineTest проверяет атомарность с журналом импорта, дедупликацию,
постер и баннер, смену URL во время скачивания, устаревший processing_token,
ограниченные повторы, потерю очереди, сбой публикации, аренду погибшего воркера,
частичную загрузку постера и потерю подтверждения commit. Отдельный тест обрабатывает
настоящую JPEG-фикстуру существующим компрессором и проверяет WebP-файлы на fake-диске.
Группа catalog_media выполняется на PostgreSQL в отдельных временных схемах.

Проверено 2026-11-13: полный suite на PHP 8.4 (Docker) и PHP 8.5 — по 852 случая,
840 успешных, 12 PostgreSQL-проверок пропущены на SQLite, 3448 assertions.
Отдельный PostgreSQL-прогон групп pgsql/catalog_import/catalog_media — 45/45,
285 assertions. PHPUnit warnings/notices не обнаружены; Pint и git diff --check
проходят. Внешний HTTP и настоящее S3-хранилище новым тестом не вызываются:
используются JPEG-фикстура, настоящий компрессор и fake-диск.

## Повторная проверка схемы 2026-11-13

Уникальные индексы title_id/kind и request_id/version одновременно обеспечивают
идентичность и покрывают поиск по соответствующим внешним ключам. Дополнительные
одноколоночные FK-индексы не нужны. Для выборки publisher создан частичный индекс
(available_at, id) WHERE completed_at IS NULL: завершённая история не увеличивает
индекс активной очереди. last_synced_at пока не индексируется: запросов выборки
по нему нет, а импорт постоянно обновляет поле.

Миграция ограничивает kind/status допустимыми значениями. PostgreSQL CHECK
проверяет положительную version, неотрицательные attempts/publish_attempts и
согласованность processing с processing_token/lease_expires_at. В SQLite
проверяются kind/status; дополнительные PostgreSQL-инварианты тестируются на PG.

Проверена установка всех настоящих миграций с нуля в отдельную PostgreSQL-БД
filmhelper_codex_smoke_20261113_01, включая pgvector, и повторное применение
последней миграции после rollback. Рабочая БД приложения не изменялась.
Дополнительно проверен реальный Redis (отдельная БД 14), queue worker, компрессор
и локальный MinIO во временном бакете: запрос стал ready, оба WebP-объекта прочитаны,
outbox завершён. Только источник JPEG заменялся локальной фикстурой. Временные
объекты и созданный для проверки бакет удалены.

Завершённые события outbox и файлы без ссылок требуют отдельной политики хранения
и периодической очистки; текущая реализация не удаляет такую историю автоматически.

После уточнения миграции и TTL: Docker PHP 8.4.27 — 861 тест, 843 успешных,
18 PostgreSQL-проверок пропущены на SQLite, 3453 assertions. Отдельно PostgreSQL —
54/54, 296 assertions. Новые тесты проверяют допустимые kind/status, положительные
версии, неотрицательные счётчики, согласованность processing с арендой/токеном
и TTL scheduler. Рабочие миграции по migrate:status остаются Pending.
